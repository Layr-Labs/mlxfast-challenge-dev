3Cost model — why depth 3 loses

Speedup factors cleanly: speedup = tok/fwd ÷ round-cost, where round-cost is the MTP round’s wall time in units of one serial forward. The prediction matches the measured speedup to ±0.005 in all nine cells. Each depth increment adds a near-constant +0.4–0.5 serial-forward-equivalents per round, while the token yield it buys shrinks with per-position acceptance.

5Methodology & caveats

  1. Combined-process timing. The driver runs serial then MTP in one process; times are its per-loop wall clocks, so speedups are intra-process ratios, not separate-invocation benchmarks.
  2. JIT / warm-cache effect — measured. Serial runs first and absorbs first-forward JIT. In a warm session the effect is ≤1%: the replicated cell (code, k=2, ×3) spread 1.02% serial / 0.71% MTP with identical speedup to two decimals. A cold first process is ~23% slower on serial (cold page cache on a 15 GB checkpoint); every matrix number was taken warm.
  3. Determinism. Greedy decode is fully deterministic: acceptance counts were bit-identical across the three replications. Only wall time varies (~1%, thermal).
  4. Sample size. Each cell is n=1 (timing noise ≈ 1%). Q/A per-position rates rest on 11–19 observations.
  5. Exactness claim. “Match” = identical token stream to serial greedy, verified in-process. Campaign-wide: 29/29 runs across two machines, up to 512 tokens, corroborated by the MTPLX reference implementation (four-way bit-identical streams on a code prompt; one zero-margin bf16 tie in 160 prose tokens). Formally: decision-level equivalence up to bf16 shape-dependent reduction geometry (an fp32 discriminator experiment showed the batched-vs-serial logit drift collapses ~30× at fp32, is independent of chunk-boundary count, and appears even with no cache involved — kernel dispatch per sequence length, not state corruption), not a bitwise proof.

6Reading the matrix

  • k = 2 is the right default. Peak on structured output (1.53× code, 1.42× Q/A) and never below break-even in this matrix (worst: prose 1.01×).
  • k = 1 is the robust floor. Never loses on any workload (1.51× / 1.10× / 1.23×) and nearly ties k=2 on code — the extra depth of k=2 buys almost nothing there because position-1 acceptance is already 88%.
  • k = 3 is never optimal here. Position-3 drafts are accepted only 16–36% of the time on long-form workloads, while each round costs a further ~0.4–0.5 forward-equivalents. (On a separate code suite k=3 did clear 1.18× — profitable, just dominated by k=2.)
  • Workload dominates depth. Code accepts 20–30 points above prose at every position; acceptance, not sequence length, is the variable that decides whether MTP pays.

Verification: red/green adversarial loop (implementation + independent audit vs the MTPLX oracle spec), 29/29 exact runs, all EOS termination branches exercised. Benchmarks collected 2026-08-12 on eigen-m5-max-128gb-3 under an exclusive model-run lock; no paging in any run.
